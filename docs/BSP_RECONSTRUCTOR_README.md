# UGC BSP Reconstructor

This experimental converter is a working geometry research prototype. Training and the verification run both used Overpass. The generator builds placements from the BSP independently of the training `.pugc`. Exact reconstruction and generalization to other BSPs remain unverified.

## Archive contents

- `ugc_reconstructor.py` trains on a BSP and PUGC sample, builds independently from a BSP, and runs a numerical audit.
- `overpass_style_model.json` contains learned associations between Source materials and orientations and native UGC models. It stores statistics, materials, mesh geometry, preferences, and Overpass calibration without the original PUGC placements.
- `ugc_meshes_187.zip` contains binary meshes for the 187 types in the sample, with internal meshes, matrices, and material names. It contains geometry only.
- `overpass_autogenerated_3000.pugc` is a BSP build with a 3,000-object cap and a 0.09 minimum scale, the sample minimum rounded to hundredths.
- `overpass_autogenerated_editor_safe_3000.pugc` uses a minimum scale of 0.1 for the editor's scale constraint.
- `Overpass_Train_vs_Independent.blend` is a Blender 5.3 comparison scene with BSP, VMF, 2,801 reference PUGC placements, and 3,000 generated placements. It embeds the corresponding native UGC meshes.
- `training_report.json`, `generation_report.json`, and `geometry_audit.json` contain measurements.
- `material_assignment.csv` records the CS material, selected object ID, UGC material paths, and scale for each selected BSP face.
- `blender_top_ref.png`, `blender_top_gen.png`, and `overpass_actual_mesh_comparison.png` are diagnostic comparisons.

## Installation

Use Python 3.11 or later with `numpy`, `scipy`, and `openssl`. CPU plots also use `matplotlib`. Blender is optional for writing `.pugc`.

```sh
python -m pip install numpy scipy matplotlib
openssl version
```

### Generate from another BSP

Set the checkout and external working-directory paths. [Assets](RESOURCES.md)

```sh
python -B "$UGC_TOOLKIT/tools/ugc_reconstructor.py" build \
  --bsp "$UGC_WORK/another_map.bsp" \
  --meshes "$UGC_ASSETS/ugc_meshes_all.zip" \
  --model "$UGC_TOOLKIT/reference/overpass/overpass_style_model.json" \
  --output "$UGC_WORK/another_map.pugc" \
  --limit 3000 \
  --report "$UGC_WORK/another_map_report.json"
```

This workflow uses persisted model features and derives the world offset from the new BSP's bounding box. Accuracy on a different map has yet to be measured.

If the editor resets scales below 0.1, add `--min-scale 0.1`. The default is 0.09, rounded to two decimals from the minimum absolute value among 8,403 scale components for 2,801 ordinary objects in `overpassbydoker (1).pugc`. The measured minimum was **0.09189033508300781** on Z for object ID 16051. Most small values were near 0.1, and one was lower. The generator has no maximum scale cap. `--min-scale` rejects values below 0.09.

To preserve current game identification metadata, pass a separate empty file freshly saved by the game with `--template-pugc empty_game_save.pugc`. The build replaces that file's scene list with new objects. Use a separate template when testing independent generation. Without it, the result may open in PUGC Editor while the game rejects it due to owner or patch metadata.

### Train on another map

```sh
python -B "$UGC_TOOLKIT/tools/ugc_reconstructor.py" train \
  --bsp "$UGC_WORK/your_map.bsp" \
  --reference "$UGC_WORK/reference.pugc" \
  --meshes "$UGC_ASSETS/ugc_meshes_all.zip" \
  --model "$UGC_WORK/new_style_model.json" \
  --report "$UGC_WORK/new_training_report.json"
```

For a new training sample, the mesh library must cover every object ID in the map. The script checks model availability and reads actual geometry bounds. Use the new `model.json` for the next independent build. Evaluate cross-map generalization with multiple different BSPs and their matching PUGC maps.

### Measure quality

```sh
python -B "$UGC_TOOLKIT/tools/ugc_reconstructor.py" audit \
  --bsp "$UGC_WORK/your_map.bsp" \
  --meshes "$UGC_ASSETS/ugc_meshes_all.zip" \
  --reference "$UGC_WORK/reference.pugc" \
  --generated "$UGC_WORK/result.pugc" \
  --report "$UGC_WORK/audit.json"
```

The audit measures nearest distances between sampled vertices. It does not compute a closed-surface RMS or Hausdorff comparison. Source prop meshes absent from the inputs are excluded.

## Overpass verification

- The BSP contains 61,697 triangles and 16,237 candidate BSP faces.
- The training example contains 2,801 ordinary UGC objects across 187 types, with devices excluded.
- The independent build contains **3,000 objects** across **93 native UGC mesh types** and zero devices. The PUGC v3 file decoded successfully.
- Selected BSP faces cover **82.33%** of the original BSP face area. Box approximations fill openings and can extend beyond irregular face boundaries. Other surfaces are omitted, so the figure measures selected area only.
- The median distance from sampled automatic-build vertices to sampled BSP vertices was **1.589 m**.
- The median distance from the automatic build to sampled reference-map vertices was **3.292 m**. **17.84%** were within 1 m.
- Exact object ID accuracy on a spatial holdout was **12.03%** across 590 objects. A most-frequent-ID baseline scored **15.42%**, so model selection underperformed the baseline.
- Blender review showed that the independent build was substantially rougher than the manual reference and sometimes filled openings with unsuitable geometry.
- Among tested reflections and rotations, X reflection and a translation near 325/474/57 m gave the closest overall point cloud match. Alignment of the diagonal bridge was unconfirmed and automatic registration remained approximate.

## Geometry and texture sources

BSP supplies compiled faces, displacement geometry, and Source material paths such as `concrete/...`, `wood/...`, and `metal/...`. PUBG models come from `bp-mesh/*.bin.gz` and material paths from their mesh sections. The generator targets similar material families. PUGC does not support free recoloring or replacing a UGC asset's texture with a Counter-Strike VTF. Exact texture matching would require corresponding native UGC assets, which the catalog lacks. Most VMT files in the BSP lack the corresponding full diffuse VTF.

External Source `prop_static` meshes require MDL/VVD/VTX files. A BSP face alone provides too little information to recover that mesh. Exact reconstruction for arbitrary maps remains open.

## Follow-up work for converter quality

1. Add supervised mappings from actual UGC meshes to corresponding Source fragments beyond nearest material and normal.
2. Match assemblies of UGC parts for stairs, windows, roofs, tunnels, and bridges.
3. Compare complete surfaces using triangles, SDFs, or occlusion and penalize blocked openings and false walls.
4. Register against multiple identified geometric landmarks.
5. Evaluate a held-out BSP with a manually authored reference PUGC.
6. Test game import and texture rendering in PUBG PC.

## 0.09 update

The minimum absolute scale measured directly in the original PUGC was 0.091890335... on Z for object ID 16051. Rounded to two decimals, this is 0.09. In the 3,000-object build, changing the minimum from 0.01 affected 494 objects and 514 components. The script removes the artificial upper scale cap and rejects `--min-scale < 0.09`. The updated position accounts for the mesh's local center offset. See `reference_min_scale_validation.json`.
